# 物流升级 · 传送带 / 分拣器 / 分流器 / 运输站 设计方案与计划

> 配套《行星发动机·工厂自动化系统设计.md》《行星发动机·实施计划与里程碑.md》。
> 目标:把当前"卡车点对点直连"的物流,升级为**两层物流** ——
> **近距离用传送带 + 分拣器 + 分流器**,**远距离用卡车,且卡车面向"装货站 / 卸货站"运输**。
>
> 铁律沿用:模拟核心零 three.js(可 node 无头测试);数据驱动(建筑/机种全在 `gamedata.js`);
> 复用现有 `Inventory` 端口、`sphere.js` 球面数学、`anchor.js` 落地矩阵、InstancedMesh 渲染、20Hz 固定步 tick。

---

## A. 现状与问题

当前物流(`systems/logistics.js`)是**需求驱动的卡车直连**:
- 端口抽象:`Provider{items}`(供货)/`Requester{needs}`(需货)/`Storage{}`(通用仓)/`Inventory{items,cap}`。
- `findJob`:先"喂需求方"(Provider→Requester),再"余量归仓"(Provider→Storage);卡车 `Hauler` 状态机 idle→to_src→load→to_sink→unload。
- 所有搬运都是**卡车从任意建筑直接开到任意建筑**。

问题 / 用户诉求:
1. 近距离(厂内、相邻机器)也用卡车,显得笨重、不像工厂流水线。
2. 希望**近距离用传送带**贴地流动,**远距离才用卡车**。
3. 卡车运输应**面向"站点"**:所有长途运输的**起点=装货站(load station),终点=卸货站(unload station)**。
4. 站点的填充/卸载由**传送带 + 分拣器**完成:
   - 装货站:传送带从矿场/机器**拉出**物品 → 直接供给装货站。
   - 卸货站:通过传送带**输出**,再用传送带 + 分拣器输入各机器。
   - 机器的产出也用传送带输入二级机器或仓库。
5. 需要**分拣器(机械臂,可过滤)**在 带↔机器/站/仓库 之间搬运;需要**分流器**做带的合流/分流/按物品路由。

## B. 目标物流拓扑(两层)

```
                       ┌──────────────── 远距离(卡车) ────────────────┐
   矿场/机器 ──带──▶ 装货站 ──▶▶ 卡车(站↔站) ▶▶──▶ 卸货站 ──带──▶ 分拣器 ──▶ 机器/仓库
             ▲(分拣器上带)                                   (分拣器下带)
             └── 近距离全程可只用带+分拣器直连相邻机器(无需卡车)
```

- **近距离链路**:机器输出口 →(分拣器)→ 传送带 →(分拣器)→ 下一机器输入口 / 仓库。全程无卡车。
- **远距离链路**:上游 →带→ 装货站(缓冲仓)→ 卡车 → 卸货站(缓冲仓)→带→ 下游。
- **卡车退化为"站间班车"**:只认装货站(源)与卸货站(汇),不再直连任意建筑。既有 `Hauler` 逻辑改造复用。
- **兼容过渡**:保留现有"卡车直连(Provider/Requester)"作为**简易模式/默认**,带系统作为**进阶精细物流**并行存在;二者都读写同一 `Inventory` 端口,可混用。

## C. 核心概念与组件(ECS)

沿用 `Inventory{items,cap}` 作为**万物端口**:机器、站点、仓库都用它收发货。带/分拣器/分流器/卡车都只是"把物品从一个 Inventory 搬到另一个"的不同策略。

### C.1 传送带 Belt
一段**测地线弧**上的**单向 FIFO 物品流**。
```
Belt {
  from:[x,y,z], to:[x,y,z],   // 两端单位方向(球面); 弧为大圆
  length,                     // 弧长(角) → 决定容量
  speed,                      // 物品前进速度(角/秒)
  items: [ { item, s } ],     // 带上物品队列, s∈[0,1] 为沿带归一化位置(尾→头)
  cap,                        // 最多承载物品数(= floor(length / spacing))
  spacing,                    // 物品最小间距(防重叠)
  inPort, outPort,            // 端口: eid+role, 或 belt 衔接(见 C.4)
}
```
- **物品模型**:每带一个数组,`s` 递增到 1 即"到达头部",尝试卸到 `outPort`;卸不掉则堵在头部(背压)。
- **背压**:头部堵住 → 后面物品停在 `spacing` 间隔处不再前进(经典传送带手感)。
- **容量**:`cap = floor(length / spacing)`;满则上游拒收(inPort 那侧的分拣器/带停手)。

> 简化实现优先:**每带一条 lane**(不做左右双道)。后续可扩展多道。

### C.2 分拣器 / 分拣臂 Inserter(含 sorter=带过滤)
在**相邻的两个端点**之间**按速率搬运单个物品**,可选**物品过滤**。
```
Inserter {
  a:{eid|belt, role:'in'|'out'},   // 取货端(机器输出口 / 带 / 站)
  b:{eid|belt, role},              // 放货端(机器输入口 / 带 / 站 / 仓库)
  rate,                            // 每秒搬运个数
  filter: null | [items],          // sorter: 只搬这些物品(null=不过滤)
  carry: {item, amt} | null,       // 手上物品(过渡)
  cooldown,
}
```
- **一端是带**时:从带头/带尾取放(带的 out/in 端)。
- **一端是机器**时:读写其 `Inventory`(遵守 Provider 只给产出、Requester 只收需求 —— 复用现有语义)。
- **filter**:sorter 版分拣器,只搬指定物品(多条不同 filter 的分拣器挂同一条带 → 实现分类下料)。

### C.3 分流器 Splitter(合流/分流/路由)
传送带的**节点**:N 条入带 + M 条出带,把入带物品按策略分到出带。
```
Splitter {
  ins:[beltId...], outs:[beltId...],
  mode: 'balance' | 'priority' | 'filter',
  filters: { beltId: [items] },   // filter 模式: 各出带只接受的物品
  rr,                             // balance 轮询指针
}
```
- `balance`:轮询平均分配。
- `priority`:优先喂前面的出带,满了再溢出到下一条。
- `filter`:按物品把入带内容路由到对应出带(分类)。

### C.4 端口衔接抽象 Port
统一"从哪取 / 放到哪":
```
Port = { kind:'inv'|'belt', eid, role }
```
- `inv`:读写实体 `Inventory`(role='provide'|'request' 决定取/放遵循 Provider/Requester 语义,或 'any' 直存直取)。
- `belt`:带的头(out)或尾(in)。
分拣器/分流器/带都以 Port 为输入输出,系统解耦。

### C.5 运输站 LoadStation / UnloadStation
卡车运输的端点,本质是**带 `Inventory` 的中转仓** + 一个"面向卡车"的角色。
```
LoadStation   { item?:filter, cap }   // 装货站: 上游(带/分拣器)填它; 对卡车表现为 Provider
UnloadStation { cap }                  // 卸货站: 卡车卸进它; 下游(带/分拣器)取走; 对卡车表现为 Requester(可配 needs)
```
- 装货站 = `Inventory` + `Provider(items)` + `LoadStation`(标记)。带/分拣器把货**塞进它**;卡车从它**取货**。
- 卸货站 = `Inventory` + `Requester(needs)` + `UnloadStation`。卡车把货**卸进它**;带/分拣器把货**取走**送下游。
- **卡车只在站间跑**:改造 `logistics`,`nearestSource` 限定 `LoadStation`,`nearestSink` 限定 `UnloadStation`(见 F)。

## D. 关键设计决策

1. **物品在带上 = 连续位置 FIFO**(非格子)。位置 `s∈[0,1]`,每 tick `s += speed·dt/length`,受前车 `spacing` 约束;到头卸货,卸不掉背压。渲染时沿弧插值。
   - 优点:实现简单、球面弧天然连续、性能好(每带 O(物品数))。
2. **一切经 `Inventory` 端口**:带/分拣器/站不发明新库存语义,复用 Provider/Requester/Storage/Inventory,和现有卡车物流无缝混用。
3. **卡车升级而非替换**:`logistics` 加"站点模式"——源限定装货站、汇限定卸货站;保留旧的"任意 Provider→Requester"作为兼容路径(可用开关或按是否存在站点自动切换)。近距离由带承担后,卡车数量大减。
4. **球面几何复用**:带弧 = `from`→`to` 的大圆(`sphere.js` 的 `moveToward`/`tangentToward` 可算方向);渲染用 `anchor.worldMatrix` 沿弧摆放段与物品。放置用现有 `anchorPick` 取两端方向。
5. **tick 顺序(关键,避免同帧穿透/抖动)**,插入现有 20Hz 固定步:
   ```
   mining_crew → power → production →
   inserters:machine→belt(上带) →
   belts(物品前进) →
   splitters(合流/分流) →
   inserters:belt→machine/station(下带) →
   logistics(站↔站卡车) → research → engine
   ```
   即"先把货放上带 → 带走一格 → 分流 → 下带 → 卡车站间搬"。顺序固定,单向数据流,天然无环。
6. **背压 = 拒收**:目标满则不搬(带满/机器输入满/站满),上游自然堆积,最终反压到源(矿场限产),与现有"矿机满仓停挖"一致。
7. **渲染都用 InstancedMesh**:带段(重复的短弧箱/箭头)、带上物品(小立方,按 item 颜色)、分拣器(摆臂)、分流器/站(建筑),沿用 `factory_render.js` 的 group 化写法与状态染色。
8. **放置交互**:带 = 两次点击(起点→终点,可多段折线);分拣器 = 点击"带 + 相邻建筑"自动吸附(取最近带段与最近建筑口);分流器/站 = 单点放置。复用 `app.js` 的模式/pick/toast 框架。

## F. 卡车物流改造(站点化)

`systems/logistics.js` 增加"站点模式":
- `nearestSource` → 限定 `LoadStation`(且 `invTotal>0`)。
- `nearestSink`/`sinkForItem` → 限定 `UnloadStation`(有 `needs` 缺口且有空位;或通用卸货)。
- 保留旧路径:若世界中**没有任何站点**,则回退到现有"任意 Provider→Requester"直连(向后兼容,不破坏已完成的里程碑)。
- 装货站作为 `Provider`、卸货站作为 `Requester` —— 现有 `findJob` 几乎可直接复用,只需把候选集从"所有 Provider/Requester"收窄到"站点",即加一个 `world.has(e,'LoadStation'|'UnloadStation')` 过滤。

> 由此:近距离(带)与远距离(卡车)自然分工;卡车只在站间跑,长途高效。

## H. 里程碑与计划(B 系列;每步都"能跑起来看到东西",附验收)

### B0 · 端口抽象 + 传送带核心(单带流动)
- **任务**:`Port` 抽象;`Belt` 组件 + `belt.js`(物品前进/背压/到头卸货);`placement` 加 belt(两点放置,存 from/to/length/cap);`factory_render` 画带弧 + 带上物品(小立方,item 颜色);`app.js` 加"放置传送带"模式(点起点→点终点)。
- **交付**:`systems/belt.js`、渲染、放置;`test_belt.mjs`。
- **验收**:一条带,一端手动喂物品(或分拣器占位直接 `invAdd` 到带尾),物品匀速前进到头 → 卸到目标 `Inventory`;带满背压;`node test_belt` 断言物品位置推进/容量/背压/到头转移。
- **依赖**:无(复用 sphere/anchor/Inventory)。

### B1 · 分拣器(带↔机器/仓库,含过滤)
- **任务**:`Inserter` 组件 + `inserter.js`(按 rate 从 a 取、往 b 放,遵守 Provider/Requester 语义,filter 过滤);`placement` 加 inserter/sorter(吸附到最近带段 + 最近建筑口);渲染(摆臂,按状态/朝向)。
- **验收**:矿场→带→分拣器→冶炼炉 全链只用带+分拣器跑通(不用卡车);sorter 只搬指定物品;目标满则停手(背压)。`test_inserter.mjs`。
- **依赖**:B0。

### B2 · 装货站 / 卸货站 + 卡车站点化
- **任务**:`LoadStation`/`UnloadStation` + `placement` 分支;`logistics.js` 站点模式(源=装货站/汇=卸货站,无站点则回退旧逻辑);装货站被带填充、卸货站经带输出。
- **验收**:矿场→带→装货站→**卡车**→卸货站→带→分拣器→冶炼炉 全链跑通;删掉站点则自动回退旧直连(现有 M2a-M8 测试不回归)。`test_stations.mjs`。
- **依赖**:B0、B1、现有 logistics。

### B3 · 分流器(合流 / 分流 / 按物品路由)
- **任务**:`Splitter` + `splitter.js`(balance/priority/filter);放置在带交叉;渲染节点。
- **验收**:一条带分到两条(平均/优先);两条合到一条;filter 把混合流分类到不同带。`test_splitter.mjs`。
- **依赖**:B0。

### B4 · 打磨
- 带折线/转弯(多段)、带↔带直连(不经分拣器)、带级(mk2 提速)、分拣器长臂跨带、放置吸附与预览、性能(带很多时的批处理/远处 LOD 隐藏)、存档(带上物品序列化)、UI(带方向箭头流动、堵塞高亮)。

## I. 与已完成里程碑的关系 / 迁移

- **不破坏 M0–M8**:带系统是**叠加**的精细物流层。世界中无带/无站点时,一切按现状(卡车直连)运行,所有现有 node 测试保持通过。
- **逐步替换**:玩家(或后续默认布局)可把关键近距链路改成"带 + 分拣器",把跨区链路改成"带→装货站→卡车→卸货站→带";卡车数量随之下降。
- **发动机燃料**同样受益:矿场废料/矿石可用带直连喂到发动机(近),或经站点长途运到远处发动机群。
