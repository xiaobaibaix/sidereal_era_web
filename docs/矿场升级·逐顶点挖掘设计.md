# 矿场升级 · 逐顶点挖掘设计

> 目标:把当前"区域整体下沉"的粗挖模型,升级成"挖机一次只啃一个地形顶点"的细挖模型。
> 多挖机自动寻找高点、互不重叠,视觉上是"一点点啃下来",更接近真实挖机作业。

---

## 一、现状回顾(为什么要改)

### 1.1 当前挖掘是怎么工作的

- **地形** = 连续高度场 `heightAt(x,y,z)`(fBm 噪声 + 运行时 edits 叠加);见 `src/terrain.js:139`。
- **挖机** 绑定矿场(`Excavator.depot`),在矿场圈定的挖掘区(`DigZone`)内"啃";
  - 每帧推进 `zone.depth`(`src/factory/systems/mining_crew.js:72`),整片圆形区域一起下沉;
  - 地形坑 = 一条 `edit { pos, radius, depth: zone.depth, falloff: 'smooth' }`,见 `setDigZone`(`src/factory/systems/mining_crew.js:170`)。
- **挖机移动** 只是在区内随机换点(`ex.digPoint = randInCap(zone.center, zone.radius*0.7)`),纯视觉,跟实际挖掘深度无关。

### 1.2 痛点

| # | 问题 | 现状代码 |
|---|------|----------|
| 1 | **粒度太粗**:挖机一挖一大片圆形下沉,不像"挖机"而像"镇压机" | `zone.depth` 单值代表整片深度 |
| 2 | **顶点无主体**:地形是连续函数,没有"被挖的某个点"概念 | `terrain.heightAt` 无顶点表 |
| 3 | **多挖机叠加无效**:多台挖机推同一个 `zone.depth`,等于一台;挖机之间没有"我挖这里,你挖那里"的协调 | 所有挖机共享 `zone.depth` |
| 4 | **无策略**:挖机不挑高处挖,区域均匀下降 | `randInCap` 随机换点 |

### 1.3 关键约束(必须保留)

- **地形渲染走 LOD 四叉树**(`src/planet.js`):mesh 顶点由 patch 分裂动态决定,**不能把"挖机挖的顶点"等同于"渲染顶点"**——它们是两层概念。
- **terrain.js 主线程/Worker 共享**(`src/terrain.js:1`):任何对 `heightAt` 的改动都要进 `TERRAIN_KEYS`(`src/planet.js:10`)并随 worker 一起传。
- **挖机→卡车→矿场→物流** 单向数据流(`mining_crew.js:5`):不能破坏。
- **存档兼容**:旧的"挖了一半"的存档要能继续运行(自动迁移)。

## 二、需求拆解

| 标号 | 需求 | 含义 |
|------|------|------|
| **R1** | 一次只挖一个"地形顶点" | 挖机一次操作影响**一个**离散采样点,而不是整片圆 |
| **R2** | 视觉上"一点点下降" | 单次挖降低幅度很小(`digStep`),连续多帧累计才看得出坑 |
| **R3** | 挖机有挖掘半径(`digReach`) | 只能挖到周围一定角距离内的顶点 |
| **R4** | 策略:先挖范围内**最高**的点 | 每次寻点都按当前 `heightAt + offset` 排序,挑最高 |
| **R5** | 多挖机找最高位置作为目标,移动过去挖 | 挖机不固定位置,顶点挖完或达不到时迁往下一个高点 |
| **R6** | 挖机之间挖掘区**不重叠** | 一台挖机锁定的顶点,其他挖机不能挖 |

## 三、方案对比

### 方案 A:微型圆区 edits(连续叠加)
- 把"挖一个顶点"实现成"在顶点方向压一个极小半径(如 digResolution/2)的 `edit`",深度=单步 `digStep`。
- edits 数组随时间线性膨胀(每挖一次 push 一条),需要节流/合并。
- ✅ 改动小,只在 `mining_crew.js` 加几行。
- ❌ edits 数组无界增长(100 台挖机 × 60tick × 10分钟 = 360 万条);heightAt 每次采样遍历全部 edits,渲染卡顿。
- ❌ "找最高顶点"没有可索引的离散顶点表,要每次扫描方向,策略实现别扭。

### 方案 B:全局离散顶点云(预生成)
- 把整个行星表面按最细 LOD 离散化成方向集合(`vertexField`),每个顶点 `{dir, baseH, offset, ownerId}`。
- ✅ 真正的"顶点"语义,完美贴合 R1/R4/R6。
- ❌ 行星表面 maxLevel(假设 12)→ 20×4^12 ≈ 3 亿顶点,**内存爆**。
- ❌ 必须稀疏化。

### 方案 C:挖掘区局部稀疏顶点网格 ✅ 推荐
- 不预生成全行星,**只在矿场圈定 DigZone 时**把挖掘区离散化成一团顶点(`zone.vertices[]`)。
- 顶点之间的角间距 = `digResolution`(可调,如 0.005 弧度 ≈ 0.3°)。
- 每个顶点:`{ dir:[x,y,z], baseH, offset, ownerId, hardLimit }`。
- `terrain.heightAt` 增加一层"顶点 offset 加权"采样(主线程/worker 都改)。
- ✅ 顶点数量受控:zoneRadius=0.05 / digResolution=0.005 → πr²/Δ² ≈ 314 顶点/矿场,100 个矿场也才 3 万顶点。
- ✅ 完美贴合 R1/R3/R4/R6(顶点是可寻址、有 owner 的离散对象)。
- ✅ 挖机/zone 解耦:顶点归 DigZone 所有,挖机临时租借(ownerId)。
- ⚠ 改动中等:terrain.js 要加顶点采样层,worker 同步;mining_crew.js 重写挖机状态机。

**决定走方案 C。** 后续各章都基于 C。

### 4.4 terrain.js 顶点采样层

`heightAt` 在原 edits 之后追加一层:

```js
function heightAt(x, y, z) {
  let h = baseHeightAt(x, y, z);
  h = applyCircularEdits(h, x, y, z);          // 旧 edits(用户刷子等)
  h = applyVertexOffsets(h, x, y, z);          // ← 新:顶点 offset 加权
  return h;
}

function applyVertexOffsets(h, x, y, z) {
  if (!digZones || digZones.length === 0) return h;
  const len = Math.hypot(x, y, z) || 1;
  const ux = x/len, uy = y/len, uz = z/len;
  for (const z of digZones) {
    // 球面距离 > zone.radius 的直接跳过(粗筛)
    const cosC = ux*z.center[0] + uy*z.center[1] + uz*z.center[2];
    if (cosC < z.cosRadiusPad) continue;       // cos(radius + padding)
    // 找最近的若干顶点, 反距离加权(IDW)
    let weight = 0, sumOffset = 0;
    for (const v of z.vertices) {
      const cos = ux*v.dir[0] + uy*v.dir[1] + uz*v.dir[2];
      if (cos <= 0) continue;
      const ang = Math.acos(cos);
      if (ang > z.resolution * 1.5) continue;  // 只算 1.5 格内的顶点
      const w = 1 / Math.max(ang, 1e-4);       // 反距离权重
      weight += w; sumOffset += v.offset * w;
    }
    if (weight > 0) h -= sumOffset / weight;   // offset 是已挖量 → 减
  }
  return h;
}
```

- 顶点表(`digZones`)通过新增 `TERRAIN_KEYS` 项 `digZoneVertices` 传给 worker,与现有 edits 一致。
- 加权用 IDW(反距离加权),保证顶点之间的过渡平滑,不会出现"阶梯"。
- 性能:每次 heightAt 采样只扫该 zone 内 1.5 格内的顶点(~7 个),不显著拖慢。

## 五、挖机状态机(新)

```
                       ┌─────────────┐
                       │   idle      │ ← 初次/无任务
                       └──────┬──────┘
                              │ 找到 targetVertex
                              ▼
                       ┌─────────────┐
                       │   seeking   │ ← 找范围内最高顶点
                       └──────┬──────┘
                              │ 锁定成功(ownerId=self)
                              ▼
                       ┌─────────────┐
        满仓 ←─────────│   moving    │ ← 朝 targetVertex.dir 移动
                       └──────┬──────┘
                              │ arrived
                              ▼
                       ┌─────────────┐
        满仓 ←─────────│   digging   │ ← 持续降低 targetVertex.offset
                       └──────┬──────┘
                              │ offset >= hardLimit 或 层挖穿
                              ▼
                       ┌─────────────┐
                       │  releasing  │ ← ownerId=null, digProgress=0, 找下一个
                       └─────────────┘
```

### 5.1 状态转换核心逻辑(伪代码)

```js
function stepExcavator(world, dt, ctx, e, reg, R) {
  const ex = world.get(e, 'Excavator');
  const mv = world.get(e, 'Mover');
  const inv = world.get(e, 'Inventory');
  const mt = reg.machineTypes[ex.typeId];

  // 满仓等卡车
  if (invTotal(inv) >= inv.cap) { ex.state = 'full'; releaseVertex(ex, world); return false; }

  // 无锁定 → 寻点
  if (ex.targetVertex == null) {
    if (ex.searchCooldown > 0) { ex.searchCooldown -= dt; return false; }
    const v = findHighestVertexInRange(world, mv.dir, ex.digReach, e, ex.depot);
    if (!v) { ex.state = 'idle'; ex.searchCooldown = 0.5; return false; }  // 半秒后再找
    v.ownerId = e; ex.targetVertex = v._idx; ex.digProgress = 0;
    mv.target = [...v.dir]; ex.state = 'moving';
    return false;
  }

  const zone = world.get(ex.depot, 'DigZone');
  const v = zone.vertices[ex.targetVertex];

  switch (ex.state) {
    case 'moving': {
      const r = moveToward(mv.dir, mv.target, (mt.speed/R)*dt);
      mv.dir = r.dir;
      if (!r.arrived) { mv.fwd = tangentToward(mv.dir, mv.target); return false; }
      ex.state = 'digging';
    } /* fallthrough */
    case 'digging': {
      ex.state = 'digging';
      const dd = Math.min(mt.digRate * dt, v.hardLimit - v.offset);  // 本 tick 挖的深度
      if (dd <= 0) { releaseVertex(ex, world); ex.targetVertex = null; return false; }
      v.offset += dd;
      ex.digProgress += dd;
      // 按当前层产出(同旧 mining.js 逻辑,只是用 v.offset 替代 m.dugDepth)
      const col = oreColumn(v.dir, reg.ore);
      const layer = layerAt(col, v.offset);
      ex.lastItem = layer ? layer.item : ex.lastItem;
      if (layer) invAdd(inv, layer.item, dd * (mt.yield || 100));
      // 挖穿极限 → 释放, 找下一个
      if (v.offset >= v.hardLimit - 1e-6) { releaseVertex(ex, world); ex.targetVertex = null; }
      return true;   // 顶点 offset 变了 → 标脏, commitTerrain
    }
  }
}

function releaseVertex(ex, world) {
  if (ex.targetVertex == null) return;
  const zone = world.get(ex.depot, 'DigZone');
  const v = zone.vertices[ex.targetVertex];
  if (v && v.ownerId === ex.eid) v.ownerId = null;  // 释放锁定
  ex.targetVertex = null; ex.digProgress = 0;
}
```

### 5.2 范围内找最高顶点

```js
function findHighestVertexInRange(world, fromDir, reach, selfEid, depotEid) {
  let best = null, bestH = -Infinity;
  const zone = world.get(depotEid, 'DigZone');
  if (!zone || !zone.vertices) return null;
  for (let i = 0; i < zone.vertices.length; i++) {
    const v = zone.vertices[i];
    if (v.ownerId != null && v.ownerId !== selfEid) continue;        // R6: 被占
    if (v.offset >= v.hardLimit - 1e-6) continue;                    // 已挖穿
    const ang = angle(fromDir, v.dir);
    if (ang > reach) continue;                                       // R3: 超范围
    const h = v.baseH - v.offset;                                    // 当前实际高度
    if (h > bestH) { bestH = h; best = { ...v, _idx: i }; }
  }
  return best;
}
```

> 满足 **R3** (范围)、**R4** (最高)、**R6** (互斥)。

### 5.3 多挖机全局"找最高位置"

按需求 **R5**:多个挖机一起挖时,要"找最高位置作为挖掘区域,移动过去"。

**理解**:挖机已绑定 depot(为了卡车路径),所以"挖掘区域"=该 depot 的 DigZone。
顶点网格覆盖整片 zone,**挖机自然会在 zone 内寻找最高顶点并移动过去**——这就是 R5 的实现。

(可选扩展)若希望挖机跨 zone 协调:可以让挖机跨 depot 寻找顶点。但会破坏卡车路径假设,默认不做。

## 六、顶点网格生成

`setDigZone` 触发,在挖掘区球冠内均匀采样:

```js
function generateVertices(zone, planet, oreData, reg) {
  const res = zone.resolution || 0.005;
  const vertices = [];
  // 球冠内六边形(轴坐标)采样 → 投影到球面
  // axis perp(垂直于 center 的两条切向基)
  const [t1, t2] = perpBasis(zone.center);
  const ringR = Math.ceil(zone.radius / res);
  for (let q = -ringR; q <= ringR; q++) {
    for (let r = -ringR; r <= ringR; r++) {
      if (Math.abs(q + r) > ringR) continue;       // 六边形外
      // axis → 球面方向
      const cx = q * 1.5, cy = (r + q/2) * Math.sqrt(3);
      const ang = Math.hypot(cx, cy) * res;        // 到 center 的角距离
      if (ang > zone.radius) continue;
      const dir = rotateCap(zone.center, t1, t2, cx*res, cy*res);
      const baseH = planet.baseHeightAt(dir[0], dir[1], dir[2]);
      // hardLimit: 该方向矿柱中最浅"过硬层"的上沿
      const col = oreColumn(dir, oreData);
      let cap = Infinity, bottom = 0;
      for (const l of col) {
        bottom = Math.max(bottom, l.d1);
        if ((l.hardness||1) > (reg.machineTypes.excavator_mk1.hardnessMax||1)) cap = Math.min(cap, l.d0);
      }
      vertices.push({ dir, baseH, offset:0, ownerId:null, hardLimit: Math.min(cap, bottom), lastItem:null });
    }
  }
  zone.vertices = vertices;
}
```

- 顶点数量:`π·(radius/res)²·(2/3√3)` ≈ `radius²/res²` × 1.2。
  默认 `radius=0.05, res=0.005` → ~314 顶点。

## 十一、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| heightAt 顶点采样拖慢 worker | 渲染掉帧 | 1.5 格邻域剪枝;digZones 数量小;profile 后再优化 |
| 顶点数过多(大 zone + 细 resolution) | 内存 / 序列化变大 | digResolution 默认 0.005;cap 上限 5000 顶点/zone |
| 多挖机抖动(频繁锁定/释放) | 视觉抖、CPU 浪费 | searchCooldown=0.5s;锁定后挖到极限才释放 |
| 旧存档 vertices 丢失 | 读档后挖机闲置 | world.load 后扫描 DigZone,自动 generateVertices |
| IDW 边缘"漏挖"(顶点之间) | 视觉平地中浮小尖 | 1.5 格加权 + 二次平滑;若仍尖,提高权重衰减幂次 |
