# 行星发动机 · 实施计划与里程碑

> 配套《行星发动机·工厂自动化系统设计.md》。本文把设计拆成**可执行、可验收**的里程碑与任务:每步给出交付文件、核心 API 契约、验收标准、依赖。
>
> 铁律:**框架一次到位、内容逐步加**;每个里程碑都产出"能跑起来看到东西"的纵向切片;模拟核心零 three.js 依赖。

---

## A. 总体策略

- **纵向切片**:每个 M 都从数据 → 逻辑 → 渲染 → 面板打通一条最小链,而不是先写完所有底层。
- **框架先行**:M0 把 ECS + 注册表 + 事件 + tick + 球面放置 + 存档骨架钉死,之后都是往里加系统/数据。
- **数据驱动**:物品/机种/配方/建筑/科技/发动机 build-plan 全是 JSON;加内容不改引擎。
- **复用现有**:`planet.js`(放置/`heightAt`/`applyEdit`)、`excavators.js`(agent 状态机/InstancedMesh/大圆移动)、`nbody.js`(推力→轨道)、浮动原点/LOD/大气管线。
- **先挂 planet_system 单星验证**,solar_system 后接(轨道逃逸终局在 solar)。

## B. 目录与模块(落地即建)

```
src/factory/
  core/
    world.js        # ECS: 实体/组件仓/系统调度/tick
    registry.js     # 数据注册表(items/machineTypes/recipes/buildings/tech/...)
    events.js       # 事件总线
    spatial.js      # 球面空间索引(cap 查询/碰撞/最近)
    save.js         # 序列化/反序列化
    anchor.js       # dir+yaw → 世界矩阵(复用 heightAt + makeBasis)
    ids.js          # 稳定 id/枚举/常量
  systems/
    mining.js  logistics.js  power.js  production.js
    population.js  research.js  construction.js  engine.js
  agents/
    agent.js        # 通用 agent(kind + 行为策略), 由 excavators 重构而来
    behaviors.js    # MineBehavior / HaulBehavior / BuildBehavior ...
  data/
    items.json  machineTypes.json  recipes.json  buildings.json  tech.json  ore.json
  render/
    factory_render.js  # world → InstancedMesh(建筑/agent/物品/塔线/喷流)
  factory.js          # 门面: 组装 world+systems+render, 给 App 用的 API
```
> `core/systems/agents/data` 纯逻辑(可 node 单测 / 可进 Worker);`render` 与 `factory.js` 接 three.js。

## C. 核心 API 契约(M0 定死,后续不轻易改)

### C.1 World(ECS)
```
createWorld() -> world
world.create(): eid
world.destroy(eid)
world.add(eid, comp, data): data      // comp = 组件名字符串
world.remove(eid, comp)
world.get(eid, comp): data | undefined
world.has(eid, comp): boolean
world.query(compA, compB, ...): Iterable<eid>   // 拥有全部这些组件的实体
world.each(comps, fn(eid, ...datas))
world.addSystem(name, fn(world, dt, ctx))        // 按加入顺序执行
world.tick(dt, ctx)                              // 依次跑系统
world.serialize(): object                        // 纯数据快照
world.load(snapshot)
```
- 组件仓实现:`Map<comp, Map<eid, data>>`(简单、可序列化;性能不够再上 SoA)。
- `ctx` 传运行期依赖(planet、registry、bus、spatial、render 钩子)。

### C.2 Registry(数据驱动)
```
registry.load({ items, machineTypes, recipes, buildings, tech, ore })
registry.items[id] / machineTypes[id] / recipes[id] / buildings[id] / tech[id]
registry.recipesFor(buildingTypeId): recipe[]
```
- 加载时校验 + 填默认;缺引用报可读错误。

### C.3 EventBus / Spatial / Anchor
```
bus.on(type, fn) -> off();  bus.emit(type, payload)
spatial.insert(eid, dir);  spatial.move(eid, dir);  spatial.remove(eid)
spatial.queryCap(dir, angRadius): eid[]           // 角半径内的实体
spatial.nearest(dir, filter?): eid | null
anchor.worldMatrix(dir, yaw, planet, out)         // dir+yaw → 落地世界矩阵(heightAt)
anchor.pick(clientX, clientY, cam, planet): dir|null   // 屏幕→地表方向(复用挖掘拾取)
```
- Spatial 起步用"粗经纬/icosphere 面 分桶";实体少时线性也行,接口先定死。

### C.4 tick 接入(App 侧)
```
// animate 里, 固定步长累加器
acc += dt; while (acc >= FIXED) { factory.tick(FIXED); acc -= FIXED; }
factory.render(alpha)   // 渲染插值(位置在两 tick 间插值)
```

## E. 里程碑逐项拆解

> 每个 M:目标 / 任务 / 交付 / 验收 / 依赖。验收里"逻辑"项尽量能 node 无头验证;"表现"项浏览器手测。

### M0 · 引擎骨架(纯逻辑,无内容)
- **任务**:`world.js`(ECS+tick)、`registry.js`、`events.js`、`spatial.js`、`save.js`、`anchor.js`;`factory.js` 门面;固定步长接入一个空 App。
- **交付**:`src/factory/core/*`、`factory.js`。
- **验收**:node 脚本建 100 实体、加/查/删组件、跑 N tick、序列化→反序列化后状态一致;`node --check` 全过。
- **依赖**:无。

### M1 · 采矿闭环(分层矿 + 表土剥离 + 一种挖机)
- **任务**:`ore.json`+`oreColumn(dir,depthFrac)`(接 terrain noise);`MiningSystem`(挖机在作业点 `applyEdit` 挖低 → 按挖穿层产出到自身 `Inventory`);`machineTypes.json`(miner_mk1);放置(`anchor.pick`+合法性)、拆除(Command);`factory_render`(miner InstancedMesh);planet_system 挂"工厂"面板(选建筑→点地表放→看到产矿数字/坑变深)。
- **交付**:`core` 用起来、`systems/mining.js`、`agents/*` 初版(miner)、`render/factory_render.js`、`data/ore.json`+`machineTypes.json`、planet_system 面板。
- **验收**:放一台矿机 → 先出废土、挖到矿层出铁矿;库存增长;地形坑可见;拆除回收。
- **依赖**:M0;复用 `planet.applyEdit`/`heightAt`、excavators 渲染/移动。

### M2 · 物流(a: agent 短途 / b: 厂内传送带)
- **M2a**:`agents/behaviors.js` HaulBehavior;`logistics.js` port 抽象 + AgentStrategy;仓库(`Inventory` 建筑);矿机→仓库自动搬运。
- **M2b**:`Belt` 组件 + BeltStrategy(测地线短带,物品队列,进/出端口);相邻机器紧密流水。
- **交付**:`systems/logistics.js`、`agents/behaviors.js`、Belt 渲染。
- **验收**:矿机产出被 hauler 送进仓库;两台相邻机器用带连起来物品流动。
- **依赖**:M1。

### M3 · 生产 / 流水线
- **任务**:`production.js`(通用配方执行器:输入齐+有电位+输出不堵→按 time 推进→产出);冶炼炉/制造台;`recipes.json`。矿→锭→零件多级跑通。
- **验收**:铁矿→(冶炼)铁锭→(制造)结构件,全自动流。
- **依赖**:M1/M2。

### M4 · 电力(输电塔覆盖 + 自动连线 + 并查集组网)
- **任务**:`PowerTower`/`Power` 组件;`power.js`(覆盖关系增量维护 + 塔塔并查集组网 + 每 tick 供需满足率);建筑 `progress *= sat`;塔→建筑/塔→塔连线渲染(变更时重建)。
- **验收**:铺塔覆盖工厂→自动连线、缺电降速、加发电站恢复。
- **依赖**:M3。

### M5 · 人口 / 小人 + 发展度 + 科技
- **任务**:`Colonist/Population` 组件;`population.js`(需求/满意度/增长)→ 派生 `DevelopmentLevel`;`research.js`(按发展度阈值+附加条件解锁,事件广播);生产转向服务民生;建造菜单/配方随解锁启用。**先做"简化发展度"(人口×基础满足)占位**,后续加深需求。
- **验收**:满足小人需求→发展度上升→到阈值解锁新建筑/配方(菜单实时变)。
- **依赖**:M3(民生品)、M4。

### M6 · 行星发动机·分阶段建造(ConstructionProject)
- **任务**:`ConstructionProject`/`ConstructionSystem`;engine build-plan 数据;阶段=选址平整(接整平/挖机)→骨架(投建材+建造 agent)→核心/配置件(现场造+L3 预制运入)→调试;L3 定制运输(站+路线+运输器);阶段/整机完成事件;多台。
- **验收**:走完各阶段造出一台(未点火)发动机;多台可并列。
- **依赖**:M2(L3)、M3、M5(科技解锁 engine_site)。

### M7 · 点火与推力(接 nbody)
- **任务**:`engine.js`(点火流程状态机;每 tick 消耗物质/燃料→算推力 `F=ṁ·ve`→写行星 `Body.externalAcc`);nbody 侧加 `externalAcc` 并在 kick 前叠加;喷流特效;轨道线随推力变化。
- **验收**:点火后行星速度矢量/轨道可见变化;多台同向合推更强。
- **依赖**:M6;`nbody.js` 小改(externalAcc 累加器)。

### M8 · 逃逸终局
- **任务**:多台推力合成与效率/物质平衡;逃逸判据 `½v²-GM/r>0` → "离开太阳系"结算;进度/剧情面板;solar_system 里跑完整轨道逃逸。
- **验收**:持续推进 → 行星脱离恒星引力束缚 → 结算。
- **依赖**:M7、solar_system 集成。

### M9 · 打磨
- 蓝图/复制、存档健壮性+版本迁移、性能(实例化/远处工厂 LOD 隐藏/模拟进 Worker)、平衡调参、UI/音效。

## G. 验收 / 测试策略
- **核心逻辑**:`src/factory/core|systems|agents` 零 three.js → 写 node 无头测试(建世界、跑 tick、断言状态、序列化往返)。每个 M 附最小测试脚本。
- **语法**:每次改完 `node --check` 相关文件。
- **表现**:`python3 serve.py` + 浏览器手测(硬刷新);冒烟 curl 200。
- **性能基线**:M9 前定"目标实体规模"(如 2k 建筑 + 500 agent),据此决定是否上 SoA/Worker。

## H. 顺序与风险(可调整点)
- **人口系统(M5)是最大不确定项**:先用简化发展度占位,别阻塞发动机主线;想加深随时回填。
- **物流 L3 与传送带分合流**:先直线大圆 + 简单端口,复杂寻路/拥堵后置。
- **性能**:实体量上来前不过早优化;Map-of-Maps 起步,基线不达标再 SoA/Worker。
- **轨道稳定性**:推力量级要配 `worldScale`/G;先在 planet_system 用简化演示,solar 里再调真实尺度。
- **存档兼容**:数据驱动 + 版本号,改配方给迁移点。
